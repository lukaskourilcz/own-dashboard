# DNESKAi Design Lab prototype

The project's review tab now opens the Lab. A List control retains the previous review surface. The prototype uses the existing `dneskai-review` tab identity, preserving hidden-tab preferences; it does not require a tab migration.

## Workspace layout (#169, 22 October 2026)

The DNESKAi workspace strip shows four tabs, in this order: **Dnes ke schválení** (For review today, opens by default), **Kalendář** (Calendar), **Příspěvky** (Posts) and **Zdroje** (Sources). Settings lists the same four under its DNESKAi heading, and each can be hidden; a hidden tab, or a project section that is not available, opens the first tab left.

Příspěvky keeps the tab id `dneskai-published` (owner decision 5), so stored hidden-tab preferences and the `user_preferences_hidden_project_tabs_check` constraint stay valid without a migration. It lists every post that is not an older version of another, latest first, with its state, time, account, the Instagram link of a published post and the code of a post in error. Filter chips Vše / Čeká / Naplánované / Publikované / Chyby narrow the list (`dneskaiPostList`, `dneskaiPostMatches`); a post in review or returned has „Otevřít v Labu“, which opens it in the Design Lab.

The `⋯` button (`aria-label` „Více“ / “More”) at the end of the tab row opens a menu. Up and Down move through it, Escape closes it and returns focus to the button. Four items open a dialog: **Chyby a náklady** (the former `dneskai-costs` tab, whose id stays in the database check), **Účet Instagram** (the account panel), **Obnova témat** (the Sources read with the owner recovery actions) and **Klávesové zkratky** (the Lab's shortcut list). Below them, under „Projekt“, the general project sections (Přehled, Úkoly & Poznámky, Aktivita, Komunikace, Repozitář, Finance, Konkurence, Znalosti, Škálování, Monetizace) select their tab; the open one joins the strip as a fifth tab. Sections hidden in Settings leave the menu as well.

Open `/projects/<project-id-or-slug>?projectTab=dneskai-review&labPost=<revision-id>&labSlide=0`. Slide indexes are zero-based. The preview equivalent is `/dev-preview?project=dneskai&projectTab=dneskai-review`; query selection survives reload. `tab` remains the application shell's parameter, so the project selection is namespaced as `projectTab` rather than overloading it.

The queue shows today and tomorrow in Prague time, with jobs, deadlines and explicit states. It initially selects a post waiting for review. The stage shows the saved revision at 390 CSS px (or the available phone width), a 3:4 profile crop and a scrollable full-size JPEG. Missing renders remain visible states. Thumbnail loads must succeed before approval. An edited draft is labelled separately: saving creates a successor revision and the Lab follows that revision before approval becomes available.

The inspector reuses field counters, media-pool swapping and the focal picker. Crop arithmetic is pinned to the vendored renderer; fit feedback calls the existing owner-scoped, rate-limited fitter after a 300 ms debounce. It makes no model call. Caption, alt text, scheduled time and verified account edits retain the existing edit contract and exact-hash semantics. The hashed fields are listed in [marketing-revision-media.md](marketing-revision-media.md#approval-hash); state kept on the revision itself changes its hash. Sources stay read-only. Returned posts can be edited manually. The old List editor retains its existing ordering/removal controls; adding slides and changing type/variant are outside this prototype's edit contract.

Unsaved changes block approval, batch approval, refresh, List switching and return/skip actions. Switching to another post asks whether to discard changes; leaving the document triggers the browser's unsaved-change prompt. Ordinary project-tab navigation uses the existing application shell. Keyboard accelerators work outside text inputs: J/K or up/down selects posts, left/right selects slides, E focuses the first field, A approves, D opens batch confirmation, R returns with a note, S opens skip confirmation, G changes profile view and ? opens help. Radix handles dialog focus and Escape.

Approve the day captures the eligible revision IDs and hashes when its dialog opens. It shows each deck, caption, account and time; every image must load before submission. The request binds each hash independently and shows per-item refusals. A failure never grants authority to a different revision. Batch failures refresh the read because a response may be lost after some approvals succeeded. Individual approvals use the existing server route and hash check.

All six kits render (vendored Quorum `893a495`): Editorial, Bold, Explainer, Magazine, Ticker and Spotlight. A kit tile or the keys 1 to 6 switch the draft's kit; the stage then shows every slide as an unsaved preview in that kit, and saving writes a revision whose deck names the kit (`kit`, left out for Editorial so older hashes stand). That revision needs its own approval. A kit the vendored studio does not register is shown, never offered, and the server refuses it with `kit-unavailable`. Spotlight is the owner's photo-led style: full-bleed photographs fading into ink, centred white headlines, two-photo before/after quote slides. Its cover can carry a second picture as a round inset: in Spotlight the cover's picture panel offers "Add a round inset picture" from the topic's pool, and "Remove the inset picture". The inset is the cover's `image-2`; switching to another kit drops it, and any other kit's server edit refuses it (`deck-edit-slots-changed`).

Every kit follows the owner's post rules of 22 October 2026 (`.claude/skills/dneskai-post-content/SKILL.md`): the first slide shows only its headline, and no slide shows a page count, a picture credit, a sources slide or text about sources. The editor offers only the fields a slide type draws, so a cover has the headline alone. An edit brings an older deck into line (`dneskaiShownDeck`): it drops its sources slide, credits and the fields its types no longer draw.

## Expired time and Publish now (22 October 2026)

The server refuses an edit whose time is not in the future or is more than six days ahead (`schedule-outside-asset-window`). A post opened after its time has passed therefore starts with the nearest possible time, at least 15 minutes ahead on a 5-minute mark (`dneskaiNextEditableTime`). A note under the time field names the original time. The editor checks the six-day window before sending.

**Publikovat hned** (Publish now) appears on a DNESKAi post in review. It is enabled only when the saved slides have loaded, no blocking state applies and the account publishes: verified, its own switch on, and both server switches true. It also works when the draft differs only in its time. The confirmation dialog shows the title, `@account`, the number of slides, the version hash and the full caption. On confirmation, `POST /api/marketing/revisions` with `action: "publish-now"` and the shown `expectedHash`:

1. refuses unless that hash is still the revision's hash and the revision is `review` and ready;
2. refuses with `publishing-disabled` unless `MARKETING_PUBLISH_ENABLED`, `MARKETING_DNESKAI_PUBLISH_ENABLED` and the account's `enabled` are all true;
3. saves a new revision with the same caption, deck and account and a time two minutes ahead (`DNESKAI_PUBLISH_NOW_LEAD_MS`), reusing the re-verified JPEGs instead of rendering;
4. approves that revision's new hash through `marketing_approve_revision`.

The pg_cron tick, every 5 minutes, publishes the queued publication, usually within 7 minutes. The request never calls Meta itself: a carousel's container polling can take minutes, longer than a request may run.

## Owner decisions 6–9 (22 October 2026)

**Moved, approve again (6).** A time change still needs a fresh approval: the time is part of the hash. A post in review whose slot passed shows „Přesunuto, znovu schválit“ in the queue and a panel above the stage naming the next free slot: one of the four DNESKAi slots (`DNESKAI_BRIEF_SLOTS`) today or tomorrow, at least 15 minutes ahead and not within an hour of another scheduled post, job or waiting topic (`dneskaiNextFreeSlot`). One button opens a confirmation with the new time, the title, the account, the slide count, the version hash and the caption. Confirming sends `action: "approve-at"` with the shown `expectedHash` and `scheduledAt`. The server checks the version as Publish now does, computes the free slot itself from the stored publications, revisions and briefs (`dneskaiServerNextFreeSlot`), and refuses with `slot-unavailable` (plus the slot it would use) or `slot-none-free` when that differs. It then runs the same helper as Publish now (`moveAndApprove`): a time-only revision that reuses the re-verified JPEGs, then the approval of its new hash. A missed post is no longer selected first when the Lab opens.

**Reminder (7).** The scheduler's minute tick ends with a `reminder` step (no lease) that writes into OwnDashboard's `notifications` table: one „first post is ready“ notification per Prague day (today, or tomorrow once its first post is rendered) and one 60 minutes before the first unapproved slot of today, keyed per slot instant (`sendDneskaiReviewReminders`). A notification the owner read or dismissed still counts as sent. The text follows `user_preferences.language` and links to the post in the Lab. `DNESKAI_REVIEW_REMINDERS_ENABLED=false` switches it off.

**Regenerate with a note (8).** A returned post, or one in review, offers „Přegenerovat s poznámkou“. The dialog takes the note (the return feedback is filled in) and states the cost, about $0.02 under the $1 daily limit. `action: "regenerate"` refuses unless `DNESKAI_REGENERATE_ENABLED=true` and the AI consent are set, the hash still matches, the post is in review or returned, its brief job exists, its slot is at least 15 minutes away, and one more job's $0.25 reservation still fits under the ceiling. It copies the brief's last job request under a new key with `ownerNote` and `replacesRevisionId`, enqueues it through `marketing_enqueue_job` (calendar current, 8 jobs per 24 hours), returns a post in review with the note, and runs the job under the scheduler's generation lease when the request has 45 s left; otherwise the next tick runs it. `executeMarketingJob` reserves under the daily ceiling before the model call, as for every DNESKAi job. Once `20261022190000_dneskai_regenerate_with_note.sql` is applied the finished job supersedes the replaced version; nothing approves the new one.

**Generate now (9).** The read lists topics of today and tomorrow whose brief is pending or ready with no job (`waiting`). The Lab day column shows each with „Vygenerovat hned“. `POST /api/marketing/dneskai/generate` checks the brief, the run (never a pilot run), the slot (30 minutes ahead) and the ceiling, takes the scheduler's briefs lease, runs the tick's own `createBriefs` for that run, and runs the admitted job as above. A refusal (`dneskai-daily-generation-budget-exhausted`, `brief-still-waiting`, `generate-now-busy` and others) is shown in words under the list.

The preview harness answers all three paid or approving actions in memory: approve-at checks the fixture's free slot, regenerate and generate now become drafting jobs, and the second paid action of a page is refused by a $1 stand-in ceiling. Design Lab stays inside the review tab (decision 10).

## Comment and message (#159)

With the server-only `DNESKAI_ENGAGEMENT_EDITOR_ENABLED=true` the read sends `capabilities.engagement: true` and the post card shows „Komentář a zpráva“ under the caption (`lab/engagement-editor.tsx`). A post with a keyword shows three fields:

- **Keyword.** Typed text turns upper case; a valid word (Latin letters and digits, 1 to 24) shows as a chip. Diacritics, spaces or punctuation mark the field invalid in place.
- **DM message.** A textarea with a 1,000-character counter and a chat-bubble preview under `@account`.
- **Public reply.** Starts with „Poslali jsme vám to do zpráv.“ (`DNESKAI_DEFAULT_PUBLIC_REPLY`), 200 characters at most. Emptied, no public reply is sent.

A post without a keyword, such as a news post, shows „Přidat klíčové slovo“; „Odebrat klíčové slovo“ takes it away again. The deck draft holds the three fields as typed. `dneskaiEditRequest` sends `engagement` only when its normalised form (trimmed, keyword upper case, empty reply left out) differs from the saved one, and `null` after a removal. That change counts in the dirty check, so Approve waits for a save, and the saved version gets a new hash that needs its own approval. `draftProblems` refuses what the server would refuse before anything is sent. An engagement-only save reuses the rendered JPEGs. Nothing is sent to commenters yet; the comment watcher (#160) has its own switch.

## Authentic preview assets

`node scripts/dneskai-preview-fixtures.mjs` deterministically regenerates six abstract synthetic source images and sixteen full-size 1080 × 1350 JPEG slides with the vendored studio. The images and all copy are fixtures, not observations or source claims. Their originals are committed so the fixture renderer can verify each sha256 before rendering an edit.

`POST /api/dev-preview/dneskai-render` accepts a bounded deck using only those known fixture hashes. It reads no owner records, fetches no URL, calls no provider and writes no storage. It refuses cross-origin requests and unknown assets. Ordinary production answers 404; development and explicit `NEXT_E2E=1` builds can render fixture edits. The guest tour in an ordinary production build does not gain this rendering endpoint; a render-dependent demo edit is unavailable there. The public `/guest` Lab is explicitly read-only: edit/approval/List controls are disabled and it calls neither fit nor render endpoints. Dev-preview post edits and approvals remain in browser memory.

The preview also exposes the six specimen sheets, `public/demo/dneskai/kit-<kit>.png` with their JSON receipts, from Quorum `893a495`. Each contains the six ADR fixture decks, 24 slides (Spotlight adds a 25th tile with the round inset). Only Editorial refuses the low-resolution cover, because only its cover bleeds the picture.
