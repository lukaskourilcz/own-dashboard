## Priority decisions

1. Fix the publishing evidence first. The CSS Grid and OpenAI dots Threads versions failed; GSA needs
   reconciliation. A failed receipt is a delivery issue, not evidence against a topic. Never resend an
   ambiguous publication blindly. This task records the issues and leaves publisher recovery to its
   existing guarded workflow.
2. Make the educational promise clear on the profile. devShark's visible bio led with a Premium discount
   and `/premium`; verify that offer before reuse and test an existing free practice destination.
   DNESKAi's current bio promises a daily technology briefing; add practical AI learning to its promise.
3. Use existing visual identities. devShark's green/ink code slides are legible. Its automatic Story
   repeats a question without an answer; test a later worked answer or recall task. DNESKAi's photo-led
   Fal cover is readable; test a relevant concept or consequence instead of valuation as the first hook.
4. Collect comparable native measurements. At 5 and 8 followers, volume and early likes cannot establish
   a winning system. Capture feed/Threads at about 72 hours and seven days; Stories near 24 hours before
   expiry. Mark account-level metrics separately from post-attributed metrics.

and intermediate web developers. The content mix to test is 40% predict/explain, 30% debugging, 20% practical
builds and 10% interview reasoning. These percentages allocate editorial effort; they do not reconfigure

completed practice only if the product actually records those events; this change does not add a tracker.

Keep 16:00 Prague Instagram/Threads and 19:00 Threads while recording a baseline. Global timing should
follow country/activity evidence, not a generic “best time” chart. The Wednesday/Friday strong-concept
rule remains intact. Test a supportive concrete challenge against status-based junior/senior teasing.

unchanged; independent Threads captions need a separate production contract before automatic use.

Technical audit notes on queued concepts: Number.EPSILON is not a universal absolute tolerance at arbitrary
scales; reverse-words code needs an empty-string case; HTTP 403 does not prove the server authenticated the
requester. The strategy records these checks without silently rewriting already approved content.

## Connected implementation

- Strategy is lazy-loaded inside the existing project workspace and respects hidden-tab preferences.
- Research and ideas remain readable when the backend is offline or the migration is missing.
- The live calendar query shares Publishing Calendar's query key. Each channel opens its exact Lab target;
  calendar details and both Labs provide a return link to the brand's Strategy.
- An idea creates one unapproved devShark concept or proposed DNESKAi topic through an authenticated,
  same-origin, owner-scoped RPC. A transaction lock and unique link prevent double-click duplicates.
  No model runs, plan fills, approval changes or publication occurs during this handoff.
- Existing approval, rendering, budgets, source checks, source rights and publication receipts remain authoritative.
- Native-Insights snapshots require an existing published receipt, actual publication/capture times and a named
  evidence reference. Missing metrics are null; measured zero remains zero. Results are append-only and exported
  with project/full account exports and a focused JSON download.
- Comparisons deduplicate a post within an age window and separate platform, format and variant. Instagram's
  primary hook metric is shares for devShark and saves for DNESKAi; Threads/Story use replies. The UI reports
  descriptive medians per 1,000 correct-denominator exposures and small-sample warnings, never an automatic winner.
- The preview uses the same in-memory Lab/topic stores. It calls no server and invents no audience metrics.

Working experiment thresholds: at least four matched posts and a sum of 500 post reach/view observations per
variant; 20% better primary rate with no deterioration in secondary outcomes is a candidate for a repeat test.
These thresholds do not establish statistical significance or 500 distinct people. Keep zero-denominator,
missing-metric, unmatched, different-format and different-age rows out of comparisons.
