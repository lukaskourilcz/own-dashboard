## Connected implementation

- Strategy is lazy-loaded inside the existing project workspace and respects hidden-tab preferences.
- Research and ideas remain readable when the backend is offline or the migration is missing.
- The live calendar query shares Publishing Calendar's query key. Each channel opens its exact Lab target;
  calendar details and both Labs provide a return link to the brand's Strategy.
- An idea creates one unapproved devShark concept or proposed DNESKAi topic through an authenticated,
  same-origin, owner-scoped RPC. A transaction lock and unique link prevent double-click duplicates.
  No model runs, plan fills, approval changes or publication occurs during this handoff.
- Existing approval, rendering, budgets, source checks, source rights and publication receipts remain authoritative.
- Native-Insights snapshots require an existing published receipt, actual publication/capture times and a named
  evidence reference. Missing metrics are null; measured zero remains zero. Results are append-only and exported
  with project/full account exports and a focused JSON download.
- Comparisons deduplicate a post within an age window and separate platform, format and variant. Instagram's
  primary hook metric is shares for devShark and saves for DNESKAi; Threads/Story use replies. The UI reports
  descriptive medians per 1,000 correct-denominator exposures and small-sample warnings, never an automatic winner.
- The preview uses the same in-memory Lab/topic stores. It calls no server and invents no audience metrics.

Working experiment thresholds: at least four matched posts and a sum of 500 post reach/view observations per
variant; 20% better primary rate with no deterioration in secondary outcomes is a candidate for a repeat test.
These thresholds do not establish statistical significance or 500 distinct people. Keep zero-denominator,
missing-metric, unmatched, different-format and different-age rows out of comparisons.
