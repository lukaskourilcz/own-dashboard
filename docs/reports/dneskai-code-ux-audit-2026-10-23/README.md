# DNESKAi code review and application UX audit

Review baseline: `d6f60c7271c8078713fe2f56d63bc71fe10a5692` on `main`, 23 October 2026.

The requested deliverable is a review and visual implementation plan. Application behavior, Production configuration and database schema are not changed by this audit. Work is isolated on `codex/dneskai-code-ux-audit-20261023` so the owner's existing checkout remains untouched.

## Method

1. Inventory every file under `src/components`, the marketing libraries and API routes, and relevant migrations.
2. Trace DNESKAi from the persistent shell through queries, authenticated routes, reads, writes, renderer and publisher.
3. Inspect authentic `/dev-preview` screens using deterministic fixture data. Record viewport, language, theme and state with each capture.
4. Confirm findings with source locations and reproductions where practical. A static pattern match is a lead, not a finding.
5. Deliver an accessible local HTML plan with current screenshots, highlighted areas, proposed component treatments and ordered acceptance criteria.

Coverage distinguishes source scanning, detailed review and browser verification. Development timing is not a Production performance benchmark. No live database query plan or accessibility pass is claimed without a recorded run.

## Design direction

Use a shared centered content grid, aligned peer modules and consistent control heights. Size operational panels around their task rather than stretching every form across the canvas. On desktop, consolidate short metadata and controls into one row when they fit. On mobile, allow deliberate wrapping, preserve 44 px touch targets and avoid truncating essential content. Equalise comparable containers; do not force unrelated workflows to have identical heights.

Keep semantic tokens, EN/CS parity, the persistent catch-all shell, lazy destination queries, own-only RLS, static FX and legal invoice output. The planned treatments are proposals, not screenshots of a finished implementation.

## Open the review

Open `index.html` in a browser with the rest of this folder beside it. It works from local files without external fonts, scripts or a server. The page includes eight component treatments, current screenshots with highlights, proposed layouts, seven code findings, all 27 destinations, a searchable 155-file component map and a 74-capture evidence gallery.

The HTML reading pages for [code findings](code-review.html), [UX recommendations](ux-audit.html) and [validation](validation.html) accompany their Markdown sources. Current screenshots live in `evidence/`; screenshots proving the review page's own layout live in `proof/`. The slide in the Lab proposal is a Chrome crop of the existing fixture render, not newly generated brand media.

To serve the folder locally, run `python3 -m http.server 3943 --bind 127.0.0.1 --directory docs/reports/dneskai-code-ux-audit-2026-10-23` from the repository root and open `http://127.0.0.1:3943/index.html`.

## Rebuild and verify

Run these from the repository root:

1. `node docs/reports/dneskai-code-ux-audit-2026-10-23/build-inventory.mjs` regenerates the AST inventory.
2. `python3 docs/reports/dneskai-code-ux-audit-2026-10-23/build-plan-data.py` builds the evidence manifest, component coverage map and browser data from the fixed audit baseline and authored recommendations.
3. `python3 docs/reports/dneskai-code-ux-audit-2026-10-23/render-reports.py` builds the three HTML reading pages.
4. `node docs/reports/dneskai-code-ux-audit-2026-10-23/verify-artifact.mjs` checks source paths/lines, local files, IDs, report anchors, highlight bounds and browser-data parity.

The four audit probes in `tests/audit/dneskai-review-baseline.test.tsx` assert observed baseline defects. They pass while those defects exist; invert or replace them with desired-behavior tests as each finding is fixed. See validation.md for the 1087-test run, type/lint results and browser limits.
