# /design-audit

1. Read `AGENTS.md`, `CLAUDE.md`, the product/design skills, and design audit/system docs.
2. Inspect the target route, server data map, shell/panel, shared components, i18n, types, APIs/migrations, and tests.
3. Walk the real user journey and every material state; distinguish repository evidence from assumptions.
4. Identify existing reuse, hierarchy/density/status/copy issues, responsive/a11y gaps, and business/security risks.
5. Compare only relevant reference principles from `docs/design/reference-research.md`.
6. Produce prioritized file-level actions with acceptance checks; when implementation is requested, perform them and validate instead of stopping at recommendations.
